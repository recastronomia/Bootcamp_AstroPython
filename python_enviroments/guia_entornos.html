Flujo de trabajo general

Antes de entrar en detalle, este es el ciclo que seguiremos en cualquier proyecto:

┌─────────────────────────────────────────────────────────┐
│  1. Crear entorno  →  2. Activar  →  3. Instalar paquetes│
│                                            ↓             │
│  6. Compartir  ←  5. Freezar deps  ←  4. Desarrollar    │
└─────────────────────────────────────────────────────────┘

Cada sección de esta guía corresponde a un paso de ese ciclo.

1. ¿Por qué aislar dependencias?

Imagina dos proyectos en tu computadora:

  • Proyecto A (análisis de curvas de luz, 2021) necesita numpy==1.21
  • Proyecto B (pipeline nuevo, 2024) necesita numpy==2.0

Si instalas todo en el sistema base, uno de los dos va a romperse. Los entornos virtuales son burbujas aisladas: cada proyecto tiene sus propios paquetes y versiones, sin interferirse.

Esto nos da dos cosas:

  1. Aislamiento — un proyecto no rompe otro
  2. Portabilidad — puedes reproducir el entorno exacto en otra máquina

2. Verificar tu instalación

Antes de crear entornos, confirmemos qué tenemos instalado.

  • pip / venv
  • conda
python --version
pip --version
conda --version
python --version
Error común: command not found

Si python no se encuentra, prueba con python3. En Windows puede ser necesario usar py en lugar de python.

Si conda no se encuentra, asegúrate de haber inicializado conda en tu shell:

conda init bash   # o zsh, fish, etc.
# luego reinicia la terminal

3. Crear y gestionar entornos

  • pip / venv
  • conda

Crear un entorno:

python -m venv nombre_entorno
# Ejemplo:
python -m venv mi_proyecto

Activar:

# macOS / Linux
source mi_proyecto/bin/activate

# Windows (PowerShell)
mi_proyecto\Scripts\Activate.ps1

# Windows (CMD)
mi_proyecto\Scripts\activate.bat

Verificar que está activo — el nombre del entorno aparece al inicio del prompt:

(mi_proyecto) $

Desactivar:

deactivate

Eliminar — simplemente borra la carpeta:

rm -rf mi_proyecto

Crear un entorno:

conda create -n nombre_entorno python=3.12
# Ejemplo:
conda create -n mi_proyecto python=3.12

Listar entornos existentes:

conda env list

Activar:

conda activate mi_proyecto

Desactivar:

conda deactivate

Eliminar:

conda remove -n mi_proyecto --all
Error común: activar en Windows con PowerShell

Si ves cannot be loaded because running scripts is disabled, ejecuta esto una vez como administrador:

Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
Buena práctica

Crea un entorno por proyecto y dale el mismo nombre que el proyecto. Evita reutilizar entornos entre proyectos distintos.

4. Instalar y controlar paquetes

Con el entorno activo, todos los paquetes se instalan de forma aislada.

  • pip / venv
  • conda

Instalar un paquete:

pip install numpy
pip install numpy==1.26.4      # versión específica
pip install "numpy>=2.0,<3.0"  # rango de versiones

Ver paquetes instalados:

pip list

Ver detalle de un paquete:

pip show numpy

Desinstalar:

pip uninstall numpy

Instalar un paquete:

conda install numpy
conda install numpy=1.26.4     # versión específica

Ver paquetes instalados:

conda list

Buscar un paquete:

conda search numpy

Desinstalar:

conda remove numpy
Error común: instalar fuera del entorno

Si instalas pip install numpy sin activar el entorno, el paquete va al sistema base y no estará disponible dentro del entorno. Siempre verifica que el entorno esté activo antes de instalar.

pip dentro de conda

Si tienes conda pero el paquete que necesitas no está en los canales de conda, puedes usar pip dentro de un entorno conda:

conda activate mi_proyecto
pip install nombre_paquete

5. Compartir dependencias

Esta es la clave de la reproducibilidad: exportar una lista exacta de los paquetes instalados para que otra persona (o tú mismo en otra máquina) pueda recrear el entorno.

  • pip / venv
  • conda

Exportar dependencias:

pip freeze > requirements.txt

El archivo requirements.txt se ve así:

numpy==2.3.0
matplotlib==3.10.3
pandas==2.3.0

Recrear el entorno desde cero:

# 1. Crear y activar un entorno nuevo
python -m venv mi_proyecto
source mi_proyecto/bin/activate

# 2. Instalar desde el archivo
pip install -r requirements.txt

Exportar entorno completo:

conda env export > environment.yml

Exportar solo los paquetes que instalaste tú (más portable):

conda env export --from-history > environment.yml

El archivo environment.yml se ve así:

name: mi_proyecto
channels:
  - defaults
dependencies:
  - python=3.12
  - numpy=2.3.0
  - matplotlib=3.10.3

Recrear el entorno:

conda env create -f environment.yml
conda activate mi_proyecto
Cuidado con pip freeze en el sistema base

Si ejecutas pip freeze sin un entorno activo, vas a exportar todos los paquetes del sistema (pueden ser cientos). El requirements.txt resultante es difícil de mantener. Siempre trabaja dentro de un entorno.

environment.yml puede no ser 100% portable entre sistemas operativos

Un environment.yml generado en Linux puede fallar en macOS o Windows si incluye dependencias específicas del sistema. Usa --from-history para exportar solo lo que pediste explícitamente.

6. Buenas prácticas

¿Qué va en el repositorio de git?

mi_proyecto/
├── .gitignore          ← incluir reglas para ignorar el entorno
├── requirements.txt    ← sí, commitear
├── environment.yml     ← sí, commitear (si usas conda)
├── src/
│   └── mi_script.py
└── venv/               ← NO commitear (pesa mucho y es reproducible)

Agrega esto a tu .gitignore:

# Entornos virtuales
venv/
.venv/
env/
nuevo_ambiente/
venv_test/

# Jupyter checkpoints
.ipynb_checkpoints/

Checklist por proyecto

Versión de Python en el README

Agrega una línea como esta al inicio de tu README:

Requiere Python 3.12+

Así evitas confusiones cuando alguien intenta reproducir tu código con una versión diferente.

7. Herramientas avanzadas (opcional)

Las herramientas anteriores (venv + pip o conda) cubren el 90% de los casos. Las siguientes son útiles cuando los proyectos crecen en complejidad.

Poetry

Poetry unifica la gestión de entornos, dependencias y publicación de paquetes en una sola herramienta. Usa pyproject.toml como archivo central (el estándar moderno de Python).

Instalación:

curl -sSL https://install.python-poetry.org | python3 -

Comandos equivalentes:

Tarea pip/venv Poetry
Crear proyecto mkdir + python -m venv poetry new mi_proyecto
Activar entorno source venv/bin/activate poetry shell
Instalar paquete pip install numpy poetry add numpy
Deps de desarrollo manual poetry add --group dev pytest
Exportar deps pip freeze > requirements.txt automático en pyproject.toml

Ventaja clave: Poetry distingue entre dependencias que pediste tú (numpy) y las que numpy necesita internamente (contourpy, pillow, etc.). El pip freeze mezcla todo.

uv

uv es una alternativa ultrarrápida a pip escrita en Rust. Compatible con los mismos archivos (requirements.txt, pyproject.toml) pero mucho más rápida para instalar.

Instalación:

curl -LsSf https://astral.sh/uv/install.sh | sh

Comandos equivalentes a pip:

uv pip install numpy          # instalar
uv pip install -r requirements.txt  # desde archivo
uv venv mi_entorno            # crear entorno virtual
¿Cuándo usar uv?

Cuando el pip install tarda demasiado (proyectos con muchas dependencias). uv puede ser 10-100x más rápido. Para proyectos pequeños, pip es suficiente.

Referencia rápida

Tarea pip / venv conda
Crear entorno python -m venv env conda create -n env python=3.12
Activar (Linux/Mac) source env/bin/activate conda activate env
Activar (Windows) env\Scripts\activate conda activate env
Desactivar deactivate conda deactivate
Instalar paquete pip install pkg conda install pkg
Ver instalados pip list conda list
Exportar deps pip freeze > requirements.txt conda env export > environment.yml
Recrear entorno pip install -r requirements.txt conda env create -f environment.yml
Eliminar entorno rm -rf env/ conda remove -n env --all
